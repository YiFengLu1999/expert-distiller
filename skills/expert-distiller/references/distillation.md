# 材料处理与综合

## 建库

```bash
python3 /path/to/expert-distiller/scripts/corpus.py ingest materials/book.md --out generated/topic-expert/references/corpus.json
python3 /path/to/expert-distiller/scripts/corpus.py search generated/topic-expert/references/corpus.json '关键问题 同义词'
```

一次 ingest 可传多个文件，输出文件必须不存在；更新时另存新库，再迁移与核对旧规则。来源 ID 由文件内容哈希导出，相同内容不重复收录。片段 ID 在文件内容与切片参数不变时稳定；编辑或重新 OCR 后会改变。

脚本保留 TXT/Markdown 行号、PDF 文件页号。Markdown 里的标题可用于人工补充章节。原文件名不是书名、作者或版本的充分证据：在 coverage.md 补充已确认的书目，未知填未知。工具不会自动 OCR，也不会识别表格布局的语义。抽检正文、章节分界、表格和公式；空 PDF 页可能是扫描页，也可能本来空白，须人工判断。

EPUB/DOCX 等先转换为带章节/段落标记的 UTF-8 Markdown。为转换产物附上原文件名、原哈希、转换工具及版本、章节/页映射；脚本记录的是转换后的文件哈希。PDF 的印刷页仅在肉眼核实映射后追加。

## 分批阅读

1. 先列来源与章节清单，并区分全文、摘录、二手摘要、用户笔记。
2. 顺序阅读拟覆盖的片段。每批记录实际 chunk ID、局部结论、未解决术语与交叉引用；跨 chunk 的条件要同时读取相邻片段。
3. 每个概念保留定义、适用范围；每条规则保留触发条件、输入信息、判断依据、行动、失效条件。没有依据时宁可不生成该规则。
4. 处理跨来源关系：一致、互补、冲突、版本变化。保留单独来源归属。只读摘要时不得给出“原书已验证”的标记。
5. 编写 coverage.md：总片段数、实际已读 ID、跳过/不可读区段、覆盖主题、缺失主题、来源版本、质量问题、更新记录。

完整覆盖指指定文本范围内所有片段确实读过，不等于领域知识完整。不完整但有用的专家可以交付，必须在技能范围与 coverage.md 明示。

## 证据强度

knowledge.json 的 kind 只使用：

- `source`：规则实质由材料明确支持，表述可以转述；证据必须包含逐字短锚点。
- `inference`：从已登记证据推导出的建议或综合；同时说明前提、推导摘要和可能失效的条件。

不要用凭空的百分数表达置信度。证据条数和词匹配分数都不代表结论可信度。来源本身也可能出错；保留其范围，不替其背书。
